Module 0

Unsupervised Learning: The Big Picture

No labels. No target variable. The algorithm must discover hidden structure entirely on its own.

Clustering

Group Similar Points Together

Partition data into groups (clusters) where members are more similar to each other than to members of other clusters. No predefined categories — the algorithm defines them.

Algorithms: K-Means, Hierarchical Agglomerative Clustering, DBSCAN, Mean Shift, Spectral Clustering

Dimensionality Reduction

Compress Without Losing Signal

Reduce the number of features while preserving the most important structure. Used for visualization, noise removal, and speeding up downstream models.

Algorithms: PCA, Kernel PCA, MDS, t-SNE, UMAP, NMF, Autoencoders

Supervised vs Unsupervised

Key Differences

  • No labels: Cannot use classification/regression metrics
  • No ground truth: Evaluation is harder — use internal metrics
  • Exploratory: You're discovering patterns, not predicting
  • Subjective: "Correct" number of clusters depends on the question
  • Use cases: Customer segmentation, anomaly detection, topic modeling, image compression, visualization
When to Use

Right Problems for Unsupervised Learning

  • No labeled data exists or labeling is expensive
  • Exploring unknown structure in new datasets
  • Preprocessing step before supervised learning
  • Anomaly / outlier detection
  • Recommendation systems (collaborative filtering)
  • Visualizing high-dimensional data
Module 1

The Curse of Dimensionality

As features increase, data becomes exponentially sparse. Distance metrics break down. This is the core challenge behind unsupervised learning at scale.

The Problem

Why More Features Hurts

As dimensions increase, the volume of the feature space grows exponentially. Points that seem "close" in 2D become equidistant in 100D — distances lose meaning. The ratio of the nearest neighbor's distance to the farthest neighbor approaches 1 in high dimensions.

To cover 1D with 0.01 spacing → 100 points
To cover 10D → 100¹⁰ = 10²⁰ points
Effects on Clustering

Why Clustering Breaks in High Dimensions

  • All pairwise distances converge to the same value
  • Cluster boundaries become meaningless
  • Need exponentially more samples to maintain data density
  • Many features are spurious correlations that add noise
  • KNN (used in many methods) becomes unreliable
Distance Metrics

Common Distance Functions

Euclidean (L2): Straight-line distance. Default. Sensitive to scale.
Manhattan (L1): Sum of absolute differences. More robust in high dimensions.
Cosine: Angle between vectors. Good for text/sparse data (direction, not magnitude).
Jaccard: |A∩B| / |A∪B|. Binary/set data. Fails on continuous GPS data (division by zero when no exact matches).

Solutions

Fighting the Curse

  • Feature selection: Remove irrelevant/redundant features
  • PCA/dimensionality reduction: Before clustering, reduce to top components
  • Domain knowledge: Manually select meaningful features
  • Regularization: Prevent models from overfitting to noise dimensions
  • More data: More samples help maintain density per dimension
⚠️
Always reduce dimensions before clustering. Apply PCA first to remove noise dimensions, then cluster in the lower-dimensional space. This improves both cluster quality and computation speed. The IBM course recommends this as a standard preprocessing step for high-dimensional data.
Module 2

K-Means Clustering

The most widely used clustering algorithm. Fast, scalable, and intuitive. Iteratively assigns points to the nearest centroid and updates centroids until convergence.

Algorithm Steps

How K-Means Works

  1. Choose k (number of clusters)
  2. Initialize k centroids (randomly or K-Means++)
  3. Assignment step: Assign each point to its nearest centroid
  4. Update step: Recalculate centroid as mean of assigned points
  5. Repeat 3–4 until centroids stop moving (convergence)
Objective: minimize Σ Σ ||xᵢ − μₖ||²
Initialization

K-Means++ vs Random

Random init: Can lead to poor local minima — centroids may cluster together. Results vary with random seed.

K-Means++ (default in sklearn): Initializes centroids spread far apart. First centroid is random; each subsequent centroid is chosen with probability proportional to distance² from existing centroids. Much more reliable and faster to converge.

Choosing k

The Elbow Method

Plot inertia (within-cluster sum of squares) vs k. Look for the "elbow" — where adding more clusters gives diminishing returns. Not always obvious — use Silhouette Score or domain knowledge to confirm.

Inertia = Σ min_k ||xᵢ − μₖ||²
Limitations

When K-Means Fails

  • Assumes spherical, equally-sized clusters
  • Sensitive to outliers (centroid = mean)
  • Must specify k in advance
  • Non-convex cluster shapes (use DBSCAN)
  • Clusters of very different densities
  • Scale-sensitive — always scale first
kmeans_clustering.py 
from sklearn.cluster import KMeans
from sklearn.preprocessing import StandardScaler
from sklearn.metrics import silhouette_score
import matplotlib.pyplot as plt
import numpy as np

# ── Always scale before clustering ────────────────────────
scaler = StandardScaler()
X_scaled = scaler.fit_transform(X)

# ── Fit K-Means ───────────────────────────────────────────
kmeans = KMeans(
    n_clusters=5,
    init='k-means++',   # smarter initialization (default)
    n_init=10,           # run 10 times, pick best inertia
    max_iter=300,
    random_state=42
)
labels = kmeans.fit_predict(X_scaled)
print(f"Inertia: {kmeans.inertia_:.2f}")
print(f"Centroids shape: {kmeans.cluster_centers_.shape}")

# ── Elbow Method ─────────────────────────────────────────
inertias = []
k_range = range(1, 11)
for k in k_range:
    km = KMeans(n_clusters=k, init='k-means++', n_init=10, random_state=42)
    km.fit(X_scaled)
    inertias.append(km.inertia_)

plt.plot(k_range, inertias, 'bo-')
plt.xlabel('Number of clusters k'); plt.ylabel('Inertia')
plt.title('Elbow Method'); plt.show()

# ── Silhouette Score (confirms elbow choice) ──────────────
sil_scores = []
for k in range(2, 11):
    km = KMeans(n_clusters=k, n_init=10, random_state=42)
    lbl = km.fit_predict(X_scaled)
    sil_scores.append(silhouette_score(X_scaled, lbl))

best_k = range(2, 11)[sil_scores.index(max(sil_scores))]
print(f"Best k by silhouette: {best_k}, score={max(sil_scores):.3f}")

# ── Per-cluster analysis ──────────────────────────────────
import pandas as pd
df['cluster'] = labels
cluster_profile = df.groupby('cluster').mean()
print(cluster_profile)

Hierarchical Agglomerative Clustering

Builds a tree of clusters from the bottom up. No need to specify k in advance — cut the dendrogram at any level to get the desired number of clusters.

Algorithm

Bottom-Up (Agglomerative)

  1. Start: each point is its own cluster
  2. Find the two closest clusters
  3. Merge them into one cluster
  4. Repeat until one cluster remains
  5. Visualize as a dendrogram

Divisive (top-down) is the opposite — split the full dataset recursively. Less common.

Linkage Criteria

How to Measure Distance Between Clusters

Single linkage: Minimum distance between points in two clusters. Elongated, chained clusters. Sensitive to outliers.

Complete linkage: Maximum distance. Compact, balanced clusters. Less sensitive to outliers.

Average linkage: Mean distance between all pairs. Good compromise.

Ward linkage (default): Minimizes total within-cluster variance. Produces the most compact, balanced clusters. Usually best choice.

Dendrogram

Reading a Dendrogram

The y-axis shows the distance at which clusters merged. The further up a merge happens, the more dissimilar those clusters are. To choose k clusters: draw a horizontal line where the dendrogram has the longest vertical spans (biggest gaps) without crossing horizontal lines. The number of lines crossed = k.

vs K-Means

Hierarchical Advantages

  • No need to pre-specify k
  • Dendrogram reveals cluster structure at every level
  • Can handle non-spherical clusters (with right linkage)
  • Deterministic — same result every run
  • Works with any distance metric
  • Cons: O(n²) memory, slow on large datasets
hierarchical_clustering.py 
from sklearn.cluster import AgglomerativeClustering
from scipy.cluster.hierarchy import dendrogram, linkage
from scipy.spatial.distance import pdist
import matplotlib.pyplot as plt

# ── Plot Dendrogram to choose k ───────────────────────────
linked = linkage(X_scaled, method='ward')  # 'single','complete','average','ward'

plt.figure(figsize=(14, 6))
dendrogram(
    linked,
    truncate_mode='lastp',   # show only last p merges
    p=30,
    leaf_font_size=8,
    show_contracted=True
)
plt.axhline(y=50, color='red', linestyle='--', label='Cut line')
plt.title('Hierarchical Clustering Dendrogram'); plt.show()

# ── Fit Agglomerative Clustering ──────────────────────────
hc = AgglomerativeClustering(
    n_clusters=4,
    linkage='ward',     # 'complete', 'average', 'single'
    metric='euclidean'  # must be 'euclidean' for ward
)
labels = hc.fit_predict(X_scaled)

# ── Without specifying n_clusters (use distance threshold) ─
hc_auto = AgglomerativeClustering(
    n_clusters=None,
    distance_threshold=50,  # cut at distance 50
    linkage='ward'
)
labels_auto = hc_auto.fit_predict(X_scaled)
print(f"Clusters found: {hc_auto.n_clusters_}")
Module 4

Density-Based Clustering: DBSCAN & Mean Shift

Find arbitrarily-shaped clusters based on data density. Identifies noise/outliers automatically. No need to specify k.

DBSCAN

Density-Based Spatial Clustering

Groups points that are closely packed together (high density regions), marking isolated points as noise/outliers. Uses two parameters:

ε (eps): Maximum radius to search for neighbors. Neighborhood size.
MinPts (min_samples): Minimum points within ε to be a core point.

Point Types

Core, Border, and Noise Points

Core point: Has ≥ MinPts neighbors within ε. Sits inside a dense region.

Border point: Has < MinPts neighbors but is within ε of a core point. On the edge of a cluster.

Noise point (outlier): Not a core point and not within ε of any core point. Labeled as −1.

label = −1 means outlier/noise
Advantages

Why DBSCAN Outshines K-Means

  • Finds arbitrarily-shaped clusters (not just spherical)
  • Automatically identifies outliers as noise
  • No need to specify k in advance
  • Robust to outliers — they don't distort centroids
  • Good for geospatial and irregularly-shaped data
Mean Shift

Centroid Migration Algorithm

Iteratively shifts each point toward the highest density region in its neighborhood (the mean of points within a bandwidth). Converges to density peaks = cluster centers. No need to specify k — bandwidth controls cluster granularity. Computationally expensive O(n²) but excellent for mode-seeking applications like image segmentation.

💡
Choosing ε for DBSCAN: Plot the k-distance graph (sorted distances to kth nearest neighbor). Look for the "knee" — the point where distance starts increasing sharply. That distance is a good ε value. Set MinPts = 2 × dimensions as a starting point (rule of thumb).
dbscan_meanshift.py 
from sklearn.cluster import DBSCAN, MeanShift, estimate_bandwidth
from sklearn.neighbors import NearestNeighbors
import numpy as np
import matplotlib.pyplot as plt

# ── Find optimal eps using k-distance graph ───────────────
nbrs = NearestNeighbors(n_neighbors=5).fit(X_scaled)
distances, _ = nbrs.kneighbors(X_scaled)
distances = np.sort(distances[:, -1])

plt.plot(distances)
plt.xlabel('Points sorted by distance'); plt.ylabel('5th Nearest Neighbor Distance')
plt.title('k-Distance Graph — look for the knee'); plt.show()

# ── Fit DBSCAN ────────────────────────────────────────────
dbscan = DBSCAN(
    eps=0.5,          # neighborhood radius — tune this!
    min_samples=5,    # minimum points to form a core (2*dims rule)
    metric='euclidean'
)
labels = dbscan.fit_predict(X_scaled)

n_clusters = len(set(labels)) - (1 if -1 in labels else 0)
n_noise    = list(labels).count(-1)
print(f"Clusters: {n_clusters}, Noise points: {n_noise}")

# Core, border, noise classification
core_mask   = np.zeros(len(labels), dtype=bool)
core_mask[dbscan.core_sample_indices_] = True
noise_mask  = labels == -1
border_mask = ~core_mask & ~noise_mask

# ── Mean Shift ────────────────────────────────────────────
bandwidth = estimate_bandwidth(X_scaled, quantile=0.2, n_samples=500)
ms = MeanShift(bandwidth=bandwidth, bin_seeding=True)
ms.fit(X_scaled)
print(f"Mean Shift clusters: {len(ms.cluster_centers_)}")

Cluster Evaluation Metrics

No labels = no accuracy. Cluster evaluation relies on internal metrics that measure cohesion and separation.

MetricWhat It MeasuresRangeBest ValueNotes
Silhouette ScoreHow similar a point is to its own cluster vs neighbors[−1, 1]Near +1Most widely used. Works without ground truth
Inertia (WCSS)Within-cluster sum of squares[0, ∞)Lower is betterOnly for K-Means. Use with elbow method
Davies-Bouldin IndexAverage ratio of within-cluster to between-cluster distance[0, ∞)Lower is betterPenalizes spread and proximity of clusters
Calinski-HarabaszRatio of between-cluster to within-cluster dispersion[0, ∞)Higher is betterFast to compute, good for comparing k values
Adjusted Rand IndexSimilarity to ground truth labels (if available)[−1, 1]Near +1Requires known labels. Good for benchmarking
Silhouette Score — The Formula

s(i) = (b − a) / max(a, b)

a = mean distance to all other points in the same cluster (cohesion). b = mean distance to all points in the nearest different cluster (separation). Score = +1 means perfectly clustered. Score = 0 means on a boundary. Score = −1 means misclassified.

cluster_evaluation.py 
from sklearn.metrics import (
    silhouette_score, silhouette_samples,
    davies_bouldin_score, calinski_harabasz_score,
    adjusted_rand_score
)
import matplotlib.pyplot as plt
import matplotlib.cm as cm
import numpy as np

# ── Core metrics ──────────────────────────────────────────
print(f"Silhouette Score:     {silhouette_score(X_scaled, labels):.3f}")
print(f"Davies-Bouldin Index: {davies_bouldin_score(X_scaled, labels):.3f}")
print(f"Calinski-Harabasz:    {calinski_harabasz_score(X_scaled, labels):.1f}")

# ── Silhouette plot (per-sample visualization) ────────────
n_clusters = len(set(labels))
sample_sil_values = silhouette_samples(X_scaled, labels)

fig, ax = plt.subplots(figsize=(8, 6))
y_lower = 10
for i in range(n_clusters):
    sil_vals = sorted(sample_sil_values[labels == i])
    y_upper = y_lower + len(sil_vals)
    color = cm.nipy_spectral(i / n_clusters)
    ax.fill_betweenx(np.arange(y_lower, y_upper), 0, sil_vals, color=color)
    y_lower = y_upper + 10
ax.axvline(x=silhouette_score(X_scaled, labels), color='red', linestyle='--')
ax.set_xlabel('Silhouette coefficient'); plt.show()

# ── Compare multiple k values across all metrics ──────────
results = []
for k in range(2, 11):
    km = KMeans(n_clusters=k, n_init=10, random_state=42)
    lbl = km.fit_predict(X_scaled)
    results.append({
        'k': k,
        'silhouette': silhouette_score(X_scaled, lbl),
        'db_index':   davies_bouldin_score(X_scaled, lbl),
        'ch_score':   calinski_harabasz_score(X_scaled, lbl),
        'inertia':    km.inertia_
    })
import pandas as pd
print(pd.DataFrame(results).set_index('k'))

Principal Component Analysis (PCA)

Linear dimensionality reduction. Finds orthogonal axes of maximum variance. The workhorse of preprocessing and visualization.

Core Concept

What PCA Does

PCA finds new orthogonal axes (Principal Components) that capture the most variance in the data. PC1 captures the most variance, PC2 the second most (orthogonal to PC1), and so on. Data is projected onto these axes, compressing dimensions while preserving maximum information.

Cov(X) → Eigendecomposition → Eigenvectors (directions) + Eigenvalues (variance explained)
Explained Variance

Choosing Number of Components

Explained variance ratio: The proportion of total variance each PC captures.

Scree plot: Plot variance explained vs component number. Look for the elbow.

Cumulative explained variance: Common practice: keep enough components to explain 95% (or 90%) of variance. Use n_components=0.95 in sklearn to do this automatically.

Assumptions & Limitations

When PCA Struggles

  • Linear relationships only — can't capture non-linear manifolds
  • Scale-sensitive — must standardize first
  • Components are not directly interpretable (linear combinations)
  • Assumes Gaussian distributions (but works reasonably outside them)
  • Removes interpretability — use NMF if interpretability matters
Use Cases

When PCA Shines

  • Preprocessing before clustering (remove noise dimensions)
  • Visualizing high-dimensional data in 2D/3D
  • Speeding up downstream ML (reduce features first)
  • Removing multicollinearity before linear regression
  • Image compression (facial recognition, medical imaging)
  • Noise filtering
pca.py 
from sklearn.decomposition import PCA
from sklearn.preprocessing import StandardScaler
import matplotlib.pyplot as plt
import numpy as np

# ── Always standardize before PCA ─────────────────────────
scaler = StandardScaler()
X_scaled = scaler.fit_transform(X)

# ── Fit PCA — explore all components first ────────────────
pca_full = PCA()
pca_full.fit(X_scaled)

# Scree plot
plt.figure(figsize=(10, 4))
plt.subplot(1, 2, 1)
plt.bar(range(1, len(pca_full.explained_variance_ratio_)+1),
        pca_full.explained_variance_ratio_)
plt.xlabel('Principal Component'); plt.ylabel('Variance Explained')

plt.subplot(1, 2, 2)
plt.plot(np.cumsum(pca_full.explained_variance_ratio_), 'o-')
plt.axhline(y=0.95, color='r', linestyle='--', label='95% threshold')
plt.xlabel('Number of Components'); plt.ylabel('Cumulative Variance')
plt.show()

# ── Fit PCA with 95% variance retention ───────────────────
pca = PCA(n_components=0.95)  # auto-selects components for 95% variance
X_pca = pca.fit_transform(X_scaled)
print(f"Original: {X.shape[1]} features → PCA: {X_pca.shape[1]} components")

# ── Inspect loadings (which original features drive each PC)
loadings = pca.components_   # shape: (n_components, n_features)
import pandas as pd
loading_df = pd.DataFrame(
    loadings.T,
    index=feature_names,
    columns=[f'PC{i+1}' for i in range(pca.n_components_)]
)
print(loading_df.abs().sort_values('PC1', ascending=False))

# ── 2D Visualization ──────────────────────────────────────
pca2d = PCA(n_components=2)
X_2d  = pca2d.fit_transform(X_scaled)
plt.scatter(X_2d[:, 0], X_2d[:, 1], c=labels, cmap='tab10', alpha=0.7)
plt.xlabel(f'PC1 ({pca2d.explained_variance_ratio_[0]*100:.1f}%)')
plt.ylabel(f'PC2 ({pca2d.explained_variance_ratio_[1]*100:.1f}%)'); plt.show()

# ── Reconstruct (inverse transform) ──────────────────────
X_reconstructed = pca.inverse_transform(X_pca)
reconstruction_error = np.mean((X_scaled - X_reconstructed) ** 2)
print(f"Reconstruction MSE: {reconstruction_error:.4f}")

Non-Linear Dimensionality Reduction

When data lives on a non-linear manifold, PCA fails. t-SNE, UMAP, and Kernel PCA reveal the true structure.

t-SNE

Preserves local structure — similar points cluster together in the 2D embedding. Excellent for visualizing clusters. Not suitable for dimensionality reduction before ML — non-deterministic, not invertible, distance between clusters is meaningless.

  • perplexity: Balances local vs global (5–50 typical)
  • Run on PCA-reduced data first for speed
  • Set random_state for reproducibility
  • Use n_components=2 or 3 only

UMAP

Faster than t-SNE, preserves more global structure, and IS suitable as a preprocessing step (invertible). The 2025 go-to for visualization and manifold learning. Scalable to millions of points.

  • n_neighbors: local neighborhood size (15 default)
  • min_dist: tightness of embedding (0.1 default)
  • n_components: output dimensions (2/3 for viz, more for preprocessing)
  • Supports supervised/semi-supervised mode

Kernel PCA

Applies the kernel trick to PCA — maps data to a higher-dimensional space via a kernel function, then applies linear PCA. Can capture non-linear relationships that standard PCA misses.

  • kernel='rbf': Gaussian. Most common.
  • kernel='poly': Polynomial relationships
  • Controlled by gamma (like SVM)
  • Not invertible by default (no inverse_transform)

MDS

Multidimensional Scaling. Preserves pairwise distances between points in the lower-dimensional embedding. Two types: metric MDS (preserves actual distances) and non-metric MDS (preserves ranks of distances).

  • Works on any distance matrix (not just Euclidean)
  • Good for visualizing dissimilarity matrices
  • Computationally expensive O(n²)
  • Classical MDS equivalent to PCA for Euclidean distances

Matrix Factorization & NMF

Decompose data matrices into interpretable parts. NMF is uniquely powerful for text, images, and any non-negative data.

NMF Core Concept

Non-Negative Matrix Factorization

Factorizes matrix V ≈ W × H where all values in V, W, and H are non-negative. Unlike PCA which allows negative components (which cancel out), NMF produces additive, parts-based representations that are more interpretable.

V ≈ W × H  |  V(n×m) = W(n×k) × H(k×m)

W: Basis components (e.g., topics, facial features). H: Activation weights (how much of each component a sample contains). k: Number of components (hyperparameter).

vs PCA

NMF vs PCA Comparison

PCA: Orthogonal components, allows negatives, global/holistic representations. Not interpretable for many domains.

NMF: Parts-based, all positive, additive. Facial components look like actual facial parts (nose, eyes, mouth). Topic model components look like actual topics. More interpretable.

Limitation: NMF is a non-convex optimization — no closed-form solution, sensitive to initialization, not unique.

Applications

Where NMF Excels

  • Topic modeling: Documents × Terms → Topics (like LDA)
  • Facial recognition: Faces decompose into interpretable parts
  • Music source separation: Mixed audio into instruments
  • Gene expression: Genes × Samples → Gene modules
  • Recommendation: Users × Items → Latent factors
  • Image compression: Pixel matrices into components
Choosing k

Number of Components

Similar to PCA's explained variance. Use reconstruction error vs k curve. Look for elbow. In topic modeling, evaluate topic coherence (human interpretability). Try multiple k values and inspect components visually. There is no single "correct" k — it's driven by the application.

nmf_matrix_factorization.py 
from sklearn.decomposition import NMF, TruncatedSVD
from sklearn.feature_extraction.text import TfidfVectorizer
import numpy as np
import pandas as pd

# ── NMF on numerical data ─────────────────────────────────
# Note: Input must be non-negative! (e.g. pixel values, word counts)
nmf = NMF(
    n_components=10,        # number of latent factors
    init='nndsvd',          # better init than random (nndsvd or nndsvda)
    max_iter=300,
    random_state=42
)
W = nmf.fit_transform(X)  # sample activations (n_samples × k)
H = nmf.components_        # basis components (k × n_features)
X_reconstructed = W @ H    # approximate reconstruction

reconstruction_error = nmf.reconstruction_err_
print(f"Reconstruction error: {reconstruction_error:.3f}")

# ── NMF for Topic Modeling (text data) ───────────────────

X_tfidf = vectorizer.fit_transform(documents)  # non-negative TF-IDF

# Print top words per topic

for topic_idx, topic in enumerate(nmf_topics.components_):
    top_words = [feature_names[i] for i in topic.argsort()[-10:][::-1]]
    print(f"Topic {topic_idx}: {', '.join(top_words)}")

# ── Compare reconstruction error vs k (choose components) ─

    model = NMF(n_components=k, init='nndsvd', random_state=42)
    model.fit(X)
    errors.append(model.reconstruction_err_)

plt.plot(range(2, 16), errors, 'o-')
plt.xlabel('Number of Components k'); plt.ylabel('Reconstruction Error')
plt.title('NMF Elbow — Choose k'); plt.show()

Professional Checklist

1

Always Scale Before Clustering or PCA

K-Means, DBSCAN, Hierarchical, and PCA are all sensitive to feature magnitude. A feature ranging 0–1000 will dominate Euclidean distances. Standardize with StandardScaler first. Exception: if scale itself is meaningful (e.g., comparing monetary amounts).

2

Reduce Dimensions Before Clustering

Apply PCA (or UMAP) to your data before clustering to remove noise dimensions that hurt distance calculations. This is particularly important for data with >20 features. A standard pipeline: StandardScaler → PCA(0.95) → KMeans.

3

Use Multiple Metrics to Validate Clusters

No single metric is definitive. Combine Silhouette Score (cohesion/separation), Davies-Bouldin Index (cluster compactness), and Calinski-Harabasz Score. Cross-reference with the elbow method. And critically — visualize the clusters. Do they make business sense?

4

Profile Your Clusters After Fitting

Clustering is only halfway — the real value comes from interpreting what each cluster means. Do df.groupby('cluster').mean() and examine the feature profiles. Assign meaningful business names (e.g., "high-value dormant customers"). This is what makes unsupervised learning actionable.

5

t-SNE Is Visualization Only — Never Use for Preprocessing

t-SNE is non-invertible, non-deterministic, and inter-cluster distances are meaningless. It's purely for visualization. For preprocessing, use PCA (linear, fast, invertible) or UMAP (non-linear, invertible, scalable). This is one of the most common mistakes in unsupervised ML practice.

6

Set random_state for Reproducibility

K-Means, t-SNE, UMAP, and NMF are all non-deterministic. Always set random_state=42 (or any fixed integer) to ensure your results are reproducible. Report the seed in papers and notebooks. Run multiple seeds and compare stability as a form of cluster validation.

FAQ — Common Pitfalls

Why does K-Means keep giving different results each run?
K-Means is sensitive to centroid initialization. With random initialization, different starting points lead to different local minima. Fix this with: (1) init='k-means++' for smarter initialization, (2) n_init=10 to run 10 times and pick the best, and (3) random_state=42 for reproducibility. The sklearn default already uses k-means++ and n_init=10, so just set the random_state.
How do I interpret the components from PCA?
Each principal component is a linear combination of original features. Inspect pca.components_ — the loadings. Features with large absolute loadings in PC1 are the primary drivers of variance. But PCA components are often uninterpretable (e.g., PC1 = 0.4×age − 0.6×income + ...). If interpretability matters, use NMF instead. For understanding which original features matter most, use feature importance from a supervised model trained on the cluster labels.
DBSCAN found too many noise points — what do I adjust?
Two options: (1) Increase eps — a larger neighborhood means more points qualify as core, fewer are labeled noise. (2) Decrease min_samples — lower density requirement means more core points. Use the k-distance graph to find a good eps. Also make sure your data is scaled — unscaled features cause eps to be applied inconsistently across dimensions. If your data has very different densities in different regions, consider HDBSCAN which adapts to variable density.
When should I use t-SNE vs UMAP?
In 2025, UMAP is preferred in almost all scenarios: it's faster (10–100x), preserves more global structure, is reproducible with fixed random_state, can transform new data, and can be used as a preprocessing step. t-SNE is only preferable when you specifically need its local-structure-preservation properties for a visualization and computational cost isn't a concern. For large datasets (>100k points), UMAP is the only practical option — t-SNE becomes impractical.
What's the difference between PCA and SVD (Truncated SVD)?
PCA centers the data (subtracts the mean) before applying SVD, then decomposes the covariance matrix. TruncatedSVD (LSA) applies SVD directly to the data matrix without centering — this is why it's used for sparse data like TF-IDF matrices (centering would destroy sparsity). For dense data, PCA and TruncatedSVD on the mean-centered data are equivalent. Use PCA for dense data, TruncatedSVD for text and other sparse matrices.

Q01Unsupervised Learning
What is the fundamental difference between supervised and unsupervised learning, and why does it make evaluation harder?
✅ No labels = no ground truth. In supervised learning you measure error against known correct answers (accuracy, F1, MSE). In unsupervised learning you're discovering unknown structure — you can't compare to "correct" answers because they don't exist. Instead you use internal metrics like Silhouette Score (how well-separated are the clusters?) which measure geometric quality, not prediction accuracy.
Q02Curse of Dimensionality
Why does the curse of dimensionality specifically break distance-based clustering algorithms?
✅ Distance concentration. In high dimensions, the ratio of the nearest to farthest neighbor distance approaches 1 — everything is approximately equidistant. When all points are the same distance from each other, clustering based on "nearest neighbors" becomes meaningless. The fix: reduce dimensions with PCA before clustering, or use algorithms that don't rely purely on distance (e.g., DBSCAN with careful eps tuning).
Q03K-Means
K-Means uses an iterative assignment and update process. What is its objective function (what is it actually minimizing)?
✅ Minimize inertia = within-cluster sum of squares (WCSS). Formally: Σ Σ ||xᵢ − μₖ||². K-Means is a greedy algorithm that alternates between assigning points to the nearest centroid and updating centroids to the mean of assigned points. It converges to a local minimum of inertia (not guaranteed to find the global minimum — hence multiple restarts via n_init).
Q04K-Means
What is K-Means++ and why is it better than random initialization?
✅ K-Means++ spreads initial centroids intelligently. First centroid: random. Each subsequent centroid: chosen from remaining points with probability proportional to distance² from the nearest existing centroid. This ensures centroids start spread across the data space, avoiding the bad local minima that plague random initialization. Result: faster convergence, better final clusters, more consistent results. This is the sklearn default.
Q05DBSCAN
In DBSCAN, what label does a noise point receive, and what makes a point a "core point"?
✅ Noise = label −1. Core = ≥ min_samples within ε. DBSCAN has three point types: Core (dense interior, ≥ min_samples neighbors within ε), Border (within ε of a core but not itself core), Noise (not core, not within ε of any core point → labeled −1). The −1 label for noise is why you need to subtract 1 from len(set(labels)) when counting clusters in DBSCAN results.
Q06Hierarchical
Which linkage criterion is generally best for producing compact, balanced clusters in hierarchical clustering?
✅ Ward linkage is the sklearn default and generally performs best for compact, roughly equal-sized clusters. It merges clusters that result in the minimum increase to total within-cluster variance — similar to K-Means' objective but in a hierarchical framework. Single linkage produces elongated "chained" clusters and is very sensitive to outliers. Complete linkage is good but tends to break large clusters. Ward + Euclidean is the go-to starting point.
Q07Cluster Metrics
A silhouette score of +0.7 vs −0.2 — what does each tell you about cluster quality?
✅ Silhouette = (b − a) / max(a, b). Where a = mean intra-cluster distance, b = mean nearest-cluster distance. Score near +1 → well inside cluster, far from others (a ≪ b). Score near 0 → on cluster boundary. Score negative → a > b, meaning the point is on average closer to another cluster than its own → likely misclustered. Use per-sample silhouette plots to identify which clusters are poorly defined.
Q08PCA
What does "explained variance ratio" mean in PCA, and how do you use it to choose the number of components?
✅ Explained variance ratio = eigenvalue / sum(eigenvalues). Each component captures a fraction of the total variance. PC1 captures the most, PC2 the second most (orthogonal to PC1), etc. Best practice: plot cumulative explained variance vs number of components. Choose the point where adding more components gives diminishing returns (the knee). Use PCA(n_components=0.95) to auto-select for 95% variance retention.
Q09PCA
Why must you standardize your features before applying PCA?
✅ Scale dominates variance. If salary ranges 0–200,000 and age ranges 18–80, salary has ~2,500× more raw variance. Without scaling, PC1 will almost entirely represent salary variation — age will be ignored. StandardScaler removes this scale bias, ensuring PCA finds genuine structural variance rather than just the feature with the largest numerical range. This is one of the most critical preprocessing steps in PCA.
Q10t-SNE
Why should t-SNE NEVER be used as a preprocessing step before feeding data into a machine learning model?
✅ t-SNE is visualization only. Key reasons: (1) Non-invertible — can't reconstruct original features. (2) Can't transform new/unseen data at prediction time. (3) Non-deterministic — different runs give different layouts. (4) Inter-cluster distances in t-SNE plots are meaningless. (5) Destroys global structure. Use PCA for linear preprocessing, UMAP for non-linear preprocessing (it's invertible and can transform new data).
Q11NMF
What constraint makes NMF produce more interpretable components than PCA?
✅ Non-negativity = additive parts. PCA components can be positive or negative, so the reconstruction involves adding and subtracting components (cancellation). NMF forces all values ≥ 0, meaning every component is purely additive. For a face: NMF components look like actual facial parts (eyes, nose, mouth), while PCA hologram-like components that subtract from each other. For text: NMF topics contain only positive word associations. Interpretability comes from this additive, parts-based decomposition.
Q12DBSCAN
DBSCAN requires two parameters: eps and min_samples. How do you find a good value for eps empirically?
✅ k-Distance Graph / knee point. Sort all points by their distance to their kth nearest neighbor (k = min_samples). Plot these sorted distances. In dense regions, this distance is small and stable. At outliers/sparse regions, it jumps sharply — this knee is your eps threshold. Points below the knee are core/border points; above are noise. Also remember: always scale your data before running DBSCAN or eps becomes scale-dependent.
Q13Clustering
K-Means fails to correctly cluster two interleaved crescent shapes (like two half-moons). Which algorithm handles this and why?
✅ DBSCAN handles arbitrary shapes. K-Means finds spherical (Voronoi) clusters — it literally draws straight-line boundaries. Crescent/moon shapes are non-convex and CANNOT be correctly separated by straight lines. DBSCAN follows density connectivity — it "traces" along dense regions, correctly identifying each crescent as one cluster. Spectral Clustering also handles this but requires specifying k. The half-moon dataset is a classic benchmark for demonstrating K-Means' limitations.
Q14PCA
You run PCA and find that the first two components explain 45% of variance. Your colleague says "PCA failed — we need 95%." How do you respond?
✅ Context matters. For 2D visualization, 45% in two components is often perfectly fine — you're seeing nearly half the structure in two dimensions, and cluster separation may still be clearly visible. For preprocessing before a downstream model, you'd use more components (targeting 90–95%). For visualization, you want 2 or 3 components to plot and 45% is acceptable. The 95% rule is a preprocessing guideline, not a fixed requirement for visualization.
Q15Metrics
The Davies-Bouldin Index is 0.4 for k=3 and 1.8 for k=5. What does this tell you?
✅ Lower Davies-Bouldin = better clusters. DB Index measures the average ratio of within-cluster scatter to between-cluster separation. Lower = clusters are tight (small within-cluster scatter) AND well-separated (large between-cluster distances). DB = 0.4 is excellent. DB = 1.8 suggests overlapping or poorly separated clusters. Combine with Silhouette Score (higher = better) and Calinski-Harabasz (higher = better) for a fuller picture.
Q16UMAP
What is the key advantage of UMAP over t-SNE that makes UMAP suitable as a preprocessing step for machine learning?
✅ UMAP is invertible and can transform new data. You can call reducer.transform(X_new) on unseen test data — the same transformation applied to training. t-SNE only produces embeddings for the training data itself; running on new data gives unrelated coordinates. UMAP also runs 10–100× faster than t-SNE and scales to millions of points. These properties make UMAP suitable for production pipelines where you need to transform incoming data at inference time.
Q17NMF
NMF requires non-negative input. Which of the following datasets is NOT appropriate for NMF without transformation?
✅ Standardized (z-scored) data has negative values. StandardScaler produces values centered at 0 with both positive and negative values — this violates NMF's non-negativity constraint. NMF requires all values ≥ 0. Word counts, pixel values, and star ratings are naturally non-negative. For z-scored data, use PCA or TruncatedSVD instead. If you must use NMF on data with negatives, you can apply MinMaxScaler to shift to [0,1] range first.
Q18Clustering Strategy
You have a customer dataset with 50 features. What is the recommended preprocessing pipeline before K-Means clustering?
✅ Scale → PCA → K-Means. This is the recommended pipeline for high-dimensional clustering. StandardScaler removes scale bias. PCA reduces noise dimensions and fights the curse of dimensionality (improving distance meaningfulness). K-Means then operates in a cleaner, lower-dimensional space. Never use t-SNE before clustering — its 2D embedding is designed for visualization only and destroys global structure that K-Means needs. Use UMAP if you need non-linear preprocessing.
Q19Elbow Method
The elbow method plots inertia vs k and sometimes shows no clear elbow. What should you do?
✅ Triangulate with multiple metrics and domain knowledge. The elbow method often produces ambiguous results on real-world data (the "elbow" is often a gradual curve, not a sharp bend). Always cross-reference: Silhouette Score (pick k with highest score), Davies-Bouldin (pick k with lowest), Calinski-Harabasz (pick k with highest). Then validate with business logic — does k=4 customer segments make actionable business sense? A statistically "optimal" k with no business interpretation is not useful.

Which of the following statements about unsupervised learning is FALSE?
✅ C is FALSE. t-SNE is the WORST choice for preprocessing before a classifier. It's non-invertible (can't transform test data), non-deterministic, destroys global structure, and cannot generalize to new data. Use PCA or UMAP for preprocessing. A is true: DBSCAN noise = label −1. B is true: unscaled PCA is dominated by high-range features.
