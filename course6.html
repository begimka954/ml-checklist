Module 1

EDA & Feature Engineering — Understanding the Data

Before building any recommender, you need to understand what data you have. The capstone uses course enrolment logs, course descriptions, genres, and user ratings.

The Dataset

What the Data Looks Like

Three key tables drive everything in this project:

  • Courses table: course_id, title, description, genre tags
  • Ratings table: user_id, course_id, rating (0 = audited, 1 = completed)
  • Enrollments table: user_id and the courses they've taken

The ratings matrix is very sparse — most users have only taken a tiny fraction of available courses, leaving most user-course pairs with no rating at all. This sparsity is the central challenge of recommender systems.

Bag of Words (BoW)

Turning Text Into Numbers

A "Bag of Words" treats a text as a collection of word counts, ignoring grammar and order. For each course description, you count how many times each word appears. The result is a vector of word frequencies — one number per word in the vocabulary.

This is the simplest and most widely used text representation in ML. Despite its simplicity ("bag" because it loses word order), it works remarkably well for finding similar documents.

Cosine Similarity

Measuring How Similar Two Things Are

Cosine similarity measures the angle between two vectors. If two courses have similar word counts, their BoW vectors point in roughly the same direction — their cosine similarity is close to 1. Totally different courses point in opposite directions — similarity close to 0.

cos(A,B) = (A · B) / (||A|| × ||B||)

Why not Euclidean distance? Euclidean is sensitive to the total size of the document (a long course description would seem more different from a short one even if they cover the same topics). Cosine is only sensitive to direction, not magnitude — perfect for text.

Key EDA Questions

What to Explore Before Building

  • What are the most popular courses? (high enrolment count)
  • What are the most common genres/topics?
  • How sparse is the ratings matrix? (% of missing ratings)
  • How many courses has the average user taken?
  • What's the distribution of completion vs audit?
eda_and_features.py
import pandas as pd
import numpy as np
from sklearn.feature_extraction.text import CountVectorizer
from sklearn.metrics.pairwise import cosine_similarity

# ── Load data ─────────────────────────────────────────────
courses = pd.read_csv('courses.csv')    # course_id, title, description
ratings = pd.read_csv('ratings.csv')    # user_id, course_id, rating

# ── Explore sparsity ──────────────────────────────────────
n_users   = ratings['user_id'].nunique()
n_courses = ratings['course_id'].nunique()
n_ratings = len(ratings)
sparsity  = 1 - (n_ratings / (n_users * n_courses))
print(f"Users: {n_users}, Courses: {n_courses}, Sparsity: {sparsity:.1%}")

# ── Bag of Words from course descriptions ────────────────
cv = CountVectorizer(
    max_features=2000,        # keep only top 2000 words
    stop_words='english',    # remove common words like "the", "is"
    ngram_range=(1, 2)        # include single words AND 2-word phrases
)
bow_matrix = cv.fit_transform(courses['description'].fillna(''))
print(f"BoW matrix shape: {bow_matrix.shape}")  # (n_courses, 2000)

# ── Cosine Similarity Matrix ──────────────────────────────
# Every course pair gets a similarity score
sim_matrix = cosine_similarity(bow_matrix)  # shape: (n_courses, n_courses)
sim_df = pd.DataFrame(sim_matrix,
                       index=courses['course_id'],
                       columns=courses['course_id'])

# Find top 5 most similar courses to a given course
def get_similar_courses(course_id, top_n=5):
    scores = sim_df[course_id].sort_values(ascending=False)
    return scores.iloc[1:top_n+1]  # exclude the course itself
Module 2

Content-Based Recommender Systems

Recommend courses based on what the courses are about, not who took them. Two flavours: course similarity (based on descriptions) and user profiles (based on genre preferences).

📚
The Librarian Analogy

A great librarian doesn't need to know what other readers thought — they know what books are about. If you loved "The Hitchhiker's Guide to the Galaxy", they'll hand you "Good Omens" because both are British comic science fiction. Content-based recommenders do the same: they look at what the item contains and find other items that contain similar things.

Approach 1: Course Similarity

Find Courses Similar to Ones You've Taken

Given the courses a user has enrolled in, find all other courses with the highest cosine similarity score to those enrolled courses. Average the similarity scores if multiple enrolments exist. Return the top-N highest scoring unseen courses.

score(target) = avg_course_in_history cosine_sim(enrolled, target)
Approach 2: User Profile × Genre Matrix

Match User Interests to Course Genres

Each course has a genre vector (e.g., [ML=1, Python=1, Cloud=0, ...]). A user's profile is the weighted sum of all their enrolled course genre vectors (weighted by their ratings).

Interest score for a new course = dot product of user's genre profile and the course's genre vector. Recommend courses where this score is highest — it measures how well the course matches the user's known interests.

interest_score = user_profile · course_genre_vector
Advantages

Why Content-Based is Great for Cold Start

  • No user history needed for item side: Works for brand new courses immediately
  • Transparent: You can explain why something was recommended ("because you took Python ML...")
  • No popularity bias: Niche courses can still get recommended to the right people
  • Handles new users reasonably: Just ask for a few genre preferences at signup
Limitations

What Content-Based Can't Do

  • Over-specialisation: Only recommends things similar to what you already know. Won't introduce you to new genres.
  • Feature quality dependent: If descriptions are poorly written, similarity is meaningless
  • Can't capture "vibe": Doesn't know that users who like course A tend to love course B — even if they're in different genres
content_based_recommender.py
# ── Approach 1: Course Similarity Recommender ─────────────
def course_similarity_recommend(user_id, ratings_df, sim_df, top_n=10):
    # Get courses this user has already taken
    enrolled = ratings_df[ratings_df['user_id'] == user_id]['course_id'].tolist()

    # For each enrolled course, find similar ones
    score_map = {}
    for c in enrolled:
        if c in sim_df.columns:
            sims = sim_df[c].drop(index=enrolled, errors='ignore')
            for course_id, score in sims.items():
                score_map[course_id] = score_map.get(course_id, 0) + score

    recommendations = (pd.Series(score_map)
                         .sort_values(ascending=False)
                         .head(top_n))
    return recommendations

# ── Approach 2: User Profile × Genre Matrix ───────────────
def user_profile_recommend(user_id, ratings_df, course_genres_df, top_n=10):
    # Get user's enrolment history with ratings
    user_data = ratings_df[ratings_df['user_id'] == user_id]
    enrolled  = user_data['course_id'].tolist()

    # Build user genre profile: weighted sum of enrolled course genre vectors
    user_genres = course_genres_df.loc[enrolled]  # genres for enrolled courses
    weights     = user_data.set_index('course_id')['rating']

    # Weight each genre vector by the rating, then sum
    weighted = user_genres.multiply(weights, axis=0)
    user_profile = weighted.sum(axis=0)  # 1D genre preference vector

    # Score all unseen courses
    unseen = course_genres_df.drop(index=enrolled, errors='ignore')
    scores = unseen.dot(user_profile)  # dot product = interest score

    return scores.sort_values(ascending=False).head(top_n)
Module 3

Collaborative Filtering & Clustering-Based Recommendations

Instead of looking at what a course is about, collaborative filtering looks at who else enrolled in it and uses their behaviour to make predictions.

👫
The Word-of-Mouth Analogy

You want a restaurant recommendation in a new city. You don't ask what ingredients the restaurants use (content-based). You ask friends who have the same taste as you — people who loved the same restaurants you loved. If your taste-twin raves about a restaurant you haven't tried, you go. That's collaborative filtering: mine the crowd's behaviour, not the item's content.

The Ratings Matrix

The Heart of Collaborative Filtering

Create a matrix where rows = users, columns = courses, and values = ratings (0 for audited, 1 for completed, NaN for not taken). This matrix is extremely sparse — most cells are empty. The goal of collaborative filtering is to fill in the blanks.

R[user, course] = predicted_rating (fill the NaNs)
Clustering-Based (K-Means + PCA)

Group Users, Recommend Within Groups

Instead of finding similar individual users, cluster all users based on their enrolment history. Apply PCA first to reduce dimensionality (users × courses is a huge matrix), then K-Means to form groups. For any user, recommend the most popular courses among their cluster-mates that they haven't taken yet.

This is a scalable alternative to pure collaborative filtering — great when user bases are in the millions.

Cold Start Problem

The Achilles Heel of Collaborative Filtering

Collaborative filtering completely fails when you have no history:

  • New user cold start: No enrolments → can't find similar users → no recommendations
  • New item cold start: No one has rated the new course → it can never be recommended

Solution: Hybrid systems — use content-based for new items/users, switch to collaborative filtering once enough data exists.

Clustering Pipeline

Step by Step

1

Build user-course matrix

Rows = users, columns = courses, values = ratings (fill NaN with 0)

2

Apply PCA

Reduce the wide matrix to ~50 principal components — fights curse of dimensionality

3

K-Means clustering

Group users into k clusters based on their PCA-reduced profiles

4

Recommend

For target user, find their cluster, get most popular unseen courses in that cluster

clustering_recommender.py
from sklearn.decomposition import PCA
from sklearn.cluster import KMeans
from sklearn.preprocessing import StandardScaler

# ── Build user-course matrix ──────────────────────────────
user_course_matrix = ratings.pivot_table(
    index='user_id',
    columns='course_id',
    values='rating'
).fillna(0)  # 0 = not taken / no opinion

# ── Dimensionality reduction ──────────────────────────────
scaler = StandardScaler()
X_scaled = scaler.fit_transform(user_course_matrix)

pca = PCA(n_components=50, random_state=42)
X_pca = pca.fit_transform(X_scaled)
print(f"Variance retained: {pca.explained_variance_ratio_.sum():.1%}")

# ── K-Means clustering ────────────────────────────────────
kmeans = KMeans(n_clusters=8, init='k-means++', n_init=10, random_state=42)
user_course_matrix['cluster'] = kmeans.fit_predict(X_pca)

# ── Recommend for a user ──────────────────────────────────
def cluster_recommend(user_id, user_course_matrix, top_n=10):
    user_cluster = user_course_matrix.loc[user_id, 'cluster']
    cluster_members = user_course_matrix[
        user_course_matrix['cluster'] == user_cluster
    ].drop(columns=['cluster'])

    # Courses the target user has NOT taken (rating == 0)
    user_taken = user_course_matrix.loc[user_id]
    unseen = user_taken[user_taken == 0].index

    # Most popular unseen courses within the cluster
    cluster_popularity = cluster_members[unseen].sum(axis=0)
    return cluster_popularity.sort_values(ascending=False).head(top_n)
Module 4

KNN-Based Collaborative Filtering

Find the users most similar to you (your nearest neighbours), then recommend what they liked that you haven't seen yet. No machine learning training phase — pure distance calculation.

🧩
Memory-Based vs Model-Based

KNN collaborative filtering is "memory-based" — it stores the entire history and looks up similar users at prediction time (like a human remembering everything). NMF (next module) is "model-based" — it compresses the data into a compact model that can predict without looking up the raw history. Memory-based is simpler and more transparent; model-based scales better to millions of users.

User-Based KNN CF

Find Similar Users, Borrow Their Taste

For a target user, compute their cosine similarity to every other user (based on their rating vectors). Find the k most similar users (neighbours). For each unseen course, average the neighbours' ratings (weighted by similarity). Recommend courses with highest predicted rating.

predicted_rating(u, c) = Σ sim(u, n) × rating(n, c) / Σ sim(u, n)
Item-Based KNN CF

Find Similar Items, Leverage Your History

Instead of finding similar users, find courses that behave similarly (i.e., the same group of users tends to enrol in both). For each unseen course, look at how similar it is to courses the user has already taken. The more the unseen course resembles your history, the higher it ranks.

Item-based CF is generally more stable than user-based — course preferences are more consistent than individual user preferences, and the item space changes less frequently than the user space.

The Surprise Library

The Go-To Library for CF in Python

The surprise library (Simple Python RecommendatIon System Engine) makes building KNN and matrix factorization recommenders easy. It handles train/test splitting, cross-validation, and multiple similarity metrics out of the box.

Key algorithms in Surprise: KNNBasic, KNNWithMeans, KNNWithZScore, SVD, NMF, BaselineOnly. Use surprise.SVD for the best performance in most cases.

Evaluation

How to Measure Recommender Quality

  • RMSE: Root Mean Squared Error between predicted and actual ratings. Lower = better.
  • MAE: Mean Absolute Error. More interpretable than RMSE.
  • Precision@K: Of the top K recommendations, what fraction are relevant?
  • Recall@K: Of all relevant items, what fraction appear in the top K?
  • Cross-validation: Always use k-fold CV with the Surprise library to get reliable estimates.
knn_collaborative_filtering.py
from surprise import Dataset, Reader, KNNBasic, SVD
from surprise.model_selection import cross_validate, train_test_split
from surprise import accuracy

# ── Load data into Surprise format ────────────────────────
reader = Reader(rating_scale=(0, 3))  # 0=not taken, 1=audit, 2=completed
data   = Dataset.load_from_df(
    ratings[['user_id', 'course_id', 'rating']], reader
)

# ── KNN-Based Collaborative Filtering ────────────────────
knn_model = KNNBasic(
    k=20,                        # number of neighbours
    sim_options={
        'name': 'cosine',         # 'pearson', 'msd' also available
        'user_based': True         # False = item-based
    }
)

# ── Cross-validation ──────────────────────────────────────
cv_results = cross_validate(knn_model, data, measures=['RMSE', 'MAE'],
                              cv=5, verbose=True)

# ── Train and predict ─────────────────────────────────────
trainset, testset = train_test_split(data, test_size=0.25)
knn_model.fit(trainset)
predictions = knn_model.test(testset)
print(f"RMSE: {accuracy.rmse(predictions):.4f}")

# ── Predict a specific rating ─────────────────────────────
pred = knn_model.predict(uid='user_42', iid='course_101')
print(f"Predicted rating: {pred.est:.2f}")

# ── Get top-N recommendations for a user ─────────────────
all_courses = ratings['course_id'].unique()
taken       = ratings[ratings['user_id']=='user_42']['course_id'].tolist()
unseen      = [c for c in all_courses if c not in taken]

preds = [(c, knn_model.predict('user_42', c).est) for c in unseen]
top10 = sorted(preds, key=lambda x: x[1], reverse=True)[:10]

NMF-Based Collaborative Filtering

Non-Negative Matrix Factorization decomposes the sparse ratings matrix into two smaller matrices representing hidden "topics" — like discovering that users who like Python and ML courses also tend to like data visualisation, even if you never explicitly told the model that.

🧩
The Hidden Taste Analogy

Imagine you don't know what genres of music exist. You only have a table of which users bought which songs. NMF would automatically discover that certain users all buy similar songs — and label that cluster "pop fans" or "jazz fans" without you ever defining those genres. It discovers the hidden structure (latent factors) from the data alone. For courses, these latent factors might be "data science enthusiasts", "cloud architects", or "frontend developers".

How NMF CF Works

Factorize the Ratings Matrix

The ratings matrix R (users × courses) is approximated as the product of two smaller matrices:

R ≈ W × H
W: users × latent factors  |  H: latent factors × courses

W tells you how much each user is associated with each latent factor (e.g., "this user is 80% data science, 20% cloud"). H tells you how much each course belongs to each latent factor. Multiply a user's W row by H to get predicted ratings for every course — including ones they haven't taken.

Number of Latent Factors

Choosing k (Number of Topics)

This is your main hyperparameter. Too few factors: the model is too general and misses nuances. Too many: the model overfits to individual users.

Practical approach: Start with k = 10–50. Use RMSE on a held-out validation set to find the optimal k. In the IBM capstone, k values between 10 and 20 typically work well for the course dataset.

NMF vs KNN CF

When to Use Each

  • KNN CF: More interpretable (you can say "these 20 users are your neighbours"). Works well on smaller datasets. No training needed — just distance calculation at prediction time. Slow at scale.
  • NMF CF: Better at scaling to millions of users. Captures latent patterns (hidden topics). Training is required but prediction is fast. Less interpretable — latent factors are abstract.

In practice: use NMF (or SVD) for production systems, KNN for prototyping or when interpretability matters.

Handling Sparse Data

The Key Challenge

Real ratings matrices are 99%+ empty. Most users have only rated a handful of courses. NMF fills in the blanks by learning the latent structure from the ratings that DO exist. This is why the approach is called "matrix completion" — you're completing the sparse matrix by learning the underlying patterns.

nmf_collaborative_filtering.py
from surprise import NMF
from surprise.model_selection import cross_validate

# ── NMF via Surprise ──────────────────────────────────────
nmf_model = NMF(
    n_factors=15,     # number of latent topics
    n_epochs=50,      # training iterations
    random_state=42
)

cv_results = cross_validate(nmf_model, data, measures=['RMSE', 'MAE'],
                              cv=5, verbose=True)

# ── NMF via sklearn (gives access to W and H matrices) ────
from sklearn.decomposition import NMF as SklearnNMF

user_course_matrix = ratings.pivot_table(
    index='user_id', columns='course_id', values='rating'
).fillna(0)

nmf = SklearnNMF(n_components=15, init='nndsvd', random_state=42)
W = nmf.fit_transform(user_course_matrix)  # users × latent_factors
H = nmf.components_                          # latent_factors × courses

# Reconstruct full predicted ratings matrix
predicted_ratings = pd.DataFrame(
    W @ H,
    index=user_course_matrix.index,
    columns=user_course_matrix.columns
)

# Get top-N recommendations for a user
def nmf_recommend(user_id, predicted_ratings, user_course_matrix, top_n=10):
    user_pred    = predicted_ratings.loc[user_id]
    already_taken = user_course_matrix.loc[user_id]
    unseen_pred  = user_pred[already_taken == 0]
    return unseen_pred.sort_values(ascending=False).head(top_n)
Module 6

Neural Network-Based Rating Prediction

Use deep learning to learn rich vector representations (embeddings) for each user and course, then predict ratings by combining those embeddings. This is the same technique behind Spotify, YouTube, and TikTok's recommendation engines.

🗺️
Embeddings as a Map

Imagine plotting every user and every course as points on a 2D map. Similar users cluster together. Similar courses cluster together. Users who'd love a course live close to that course on the map. An embedding network learns to create this map automatically — so that predicting a rating is as simple as measuring the distance between a user point and a course point on the map. The network learns the entire map from the rating history.

Embedding Layers

What Are Embeddings?

An Embedding layer converts a discrete ID (like user_42 or course_101) into a dense vector of real numbers (e.g., a 32-dimensional vector). These vectors are learned during training — they capture the "essence" of each user or course in a compact numerical form.

Think of it as a lookup table: each ID gets its own row of numbers, and those numbers are adjusted by backpropagation to best predict ratings.

Interaction Features

Combining User + Course Embeddings

Once you have user embedding u and item embedding c, combine them to predict the rating. Common approaches:

  • Dot product: Simple inner product u·c. Fast but limited expressive power
  • Concatenate + Dense: Stack [u, c] into one vector, pass through Dense layers. More expressive.
  • Element-wise multiply: u ⊙ c, then Dense layers. Interaction features.

The IBM capstone uses the concatenation approach — extract user and item embedding vectors and use them as input features for downstream regression or classification models.

Regression vs Classification

Two Ways to Predict Ratings

Regression approach: Predict the exact rating score (a continuous number). Use MSE as the loss. Output: a single number predicting how much the user will like the course.

Classification approach: Predict the rating mode — did the user audit (0) or complete (1) the course? Use binary cross-entropy. Output: probability of completion.

In practice: try both and compare. The classification framing often works better when ratings are discrete and imbalanced.

Why Neural Embeddings Win at Scale

The Key Advantages

  • Learns non-linear interactions between user and course features
  • Can incorporate additional features (course difficulty, user demographics)
  • Scales to billions of users and items
  • The learned embeddings can be reused across many downstream tasks
  • State of the art for large recommendation systems (YouTube, Netflix, Spotify)
neural_embedding_recommender.py
import tensorflow as tf
from tensorflow.keras import layers, Model, Input

# ── Encode user and course IDs as integers ─────────────────
from sklearn.preprocessing import LabelEncoder
user_enc   = LabelEncoder()
course_enc = LabelEncoder()
ratings['user_idx']   = user_enc.fit_transform(ratings['user_id'])
ratings['course_idx'] = course_enc.fit_transform(ratings['course_id'])

n_users   = ratings['user_idx'].nunique()
n_courses = ratings['course_idx'].nunique()
EMBED_DIM = 32  # size of each embedding vector

# ── Build Neural CF Model ─────────────────────────────────
user_input   = Input(shape=(1,), name='user_input')
course_input = Input(shape=(1,), name='course_input')

# Embedding lookup: ID integer → dense vector
user_emb   = layers.Embedding(n_users,   EMBED_DIM)(user_input)
course_emb = layers.Embedding(n_courses, EMBED_DIM)(course_input)

# Flatten and concatenate user + course embeddings
user_vec   = layers.Flatten()(user_emb)
course_vec = layers.Flatten()(course_emb)
combined   = layers.Concatenate()([user_vec, course_vec])  # shape: (64,)

# Dense layers to learn interaction patterns
x = layers.Dense(128, activation='relu')(combined)
x = layers.Dropout(0.3)(x)
x = layers.Dense(64,  activation='relu')(x)
x = layers.Dropout(0.2)(x)

# Regression output: predict rating score
output = layers.Dense(1, activation='linear')(x)

model = Model([user_input, course_input], output)
model.compile(optimizer='adam', loss='mse', metrics=['mae'])

# ── Train ─────────────────────────────────────────────────
model.fit(
    [ratings['user_idx'], ratings['course_idx']],
    ratings['rating'],
    epochs=30, batch_size=256, validation_split=0.2
)

# ── Extract embeddings for downstream use ─────────────────
user_embedding_model = Model(user_input, user_vec)
user_embeddings = user_embedding_model.predict(all_user_ids)

Deploying With Streamlit

Streamlit lets you turn a Python script into a shareable web app in minutes — no HTML, CSS, or JavaScript required. For the capstone, you build an interactive dashboard that lets anyone try all five recommender methods.

🚀
Why Streamlit Changed Everything for Data Scientists

Before Streamlit, deploying an ML model as a web app required learning Flask, Docker, JavaScript, and cloud platforms — a multi-day project for a non-software-engineer. Streamlit reduced it to: write Python, run one command, get a web app. That's genuinely revolutionary. Your capstone Streamlit app demonstrates to employers that you can take an ML model all the way from research notebook to deployed product.

Core Streamlit Concepts

The Building Blocks You Need

  • st.title / st.header: Text and headings
  • st.selectbox / st.multiselect: Dropdown menus for user input
  • st.slider: Numeric input with a slider
  • st.button: Trigger model training or prediction
  • st.dataframe / st.table: Display pandas DataFrames
  • st.cache_data / st.cache_resource: Cache slow operations (loading data, training models)
  • st.sidebar: Put controls in a collapsible sidebar

Performance Tips

Making the App Fast

  • Use @st.cache_data on data loading functions — runs only once, cached for subsequent interactions
  • Use @st.cache_resource for model objects (neural networks, trained KNN models) — saves re-training on every button click
  • Pre-compute the similarity matrix and store as a CSV — don't recompute on every request
  • For neural network models: save weights with model.save() and load on startup

# ── Page config ───────────────────────────────────────────

# ── Load data (cached so it only loads once) ──────────────

Common Questions

Why does cosine similarity work better than Euclidean for text and ratings?
Cosine similarity measures the angle between two vectors, ignoring their magnitude. For text (Bag of Words), a long document and a short document about the same topic will have different magnitudes but similar directions — cosine correctly identifies them as similar. For ratings, a user who rated 10 courses all as "2" and a user who rated 10 courses all as "1" might have similar preferences — cosine captures this (same direction) while Euclidean would say they're far apart. Euclidean is better for raw coordinates in physical space; cosine is better for high-dimensional feature spaces like text and ratings.
What's the difference between content-based and collaborative filtering in simple terms?
Content-based: "Here are things similar to what you've liked based on what the ITEMS are." (Like a librarian recommending books by genre.) Collaborative filtering: "Here are things similar to what you've liked based on what PEOPLE LIKE YOU have liked." (Like asking taste-twin friends.) Content-based needs good item descriptions but no user history. Collaborative filtering needs rich interaction history but no item descriptions. Hybrid systems use both — content-based for cold start, collaborative filtering once enough data exists.
My RMSE is lower with NMF than KNN. Should I always prefer NMF?
Lower RMSE is better but not the only consideration. NMF requires training time and may be harder to update when new users or courses appear (requires re-training). KNN requires no training but is slow at prediction time (computes all pairwise similarities). SVD (matrix factorisation via singular value decomposition) typically achieves the best RMSE in practice and is used in production systems. For the capstone: use all methods, report all metrics, explain the trade-offs, and recommend one for production with clear reasoning. That analysis is what gets you the best peer review score.
The neural network model predicts ratings worse than NMF on the small capstone dataset. Is that expected?
Yes, completely expected. Neural networks require large amounts of data to learn useful representations. On the small IBM capstone dataset (a few thousand users and courses), simple methods like NMF and SVD almost always outperform neural approaches. Neural collaborative filtering (NCF) truly shines at the scale of Netflix or Spotify — hundreds of millions of users and items. Acknowledging this in your report shows mature understanding and will impress reviewers.

Q01Recommender Systems
What is the fundamental difference between content-based and collaborative filtering recommender systems?
✅ Features vs Behaviour. Content-based: "You liked this course about Python ML, here are other Python ML courses." Uses item features (descriptions, genres). Collaborative: "Users with similar histories to you also enrolled in these courses." Uses user-item interaction patterns. The distinction matters enormously in practice because they fail in completely different ways and have different cold start vulnerabilities.
Q02Bag of Words
What does a "Bag of Words" representation actually capture — and what important information does it deliberately discard?
✅ Word counts, no order. BoW creates a vector where each position represents a word and the value is how many times that word appeared. "The dog bit the cat" and "the cat bit the dog" produce identical BoW vectors — order is completely lost. Despite this simplicity, BoW is surprisingly effective for finding topically similar documents because the presence and frequency of specific words strongly predicts topic. For capturing meaning more richly, TF-IDF (penalises common words) and Word2Vec/BERT (captures context) are more sophisticated alternatives.
Q03Cosine Similarity
Two courses have a cosine similarity of 0.95. A third course has a cosine similarity of 0.3 with the first course. What does this mean?
✅ Cosine = direction similarity, not overlap percentage. Cosine similarity of 0.95 means the angle between the two BoW vectors is about 18° — they're nearly parallel in feature space, meaning they discuss very similar topics with similar word distributions. Score of 0.3 means a ~72° angle — substantially different topics. A score of 1.0 = identical direction (same topics), 0 = perpendicular (completely unrelated), −1 = opposite (theoretical extreme). Cosine doesn't measure the percentage of identical words — it measures how similarly the words are distributed.
Q04Cold Start
A brand new user signs up with no enrolment history. Which recommender will completely fail, and which will still work?
✅ Cold start is collaborative filtering's weakness. CF needs to compare the new user's history to other users' histories — with zero history, there's nothing to compare. Content-based can still work if you ask for initial preferences ("What topics interest you?") since it only needs to match user interests to course descriptions. This is why real-world systems like Netflix show genre preference surveys at signup — they're bootstrapping a content-based profile until they have enough click history for collaborative filtering to kick in.
Q05User Profile
How is a user's genre profile computed in the content-based user profile recommender?
✅ Weighted sum of enrolled course genre vectors. Each course has a genre vector (e.g., [ML=1, Python=1, Cloud=0, Frontend=0]). The user's profile = Σ (rating × genre_vector) for each enrolled course. Higher-rated courses contribute more to the profile. The result is a vector representing the user's genre interests. Dot-producting this with any course's genre vector gives an "interest score" — how well the course matches the user's taste. This is interpretable and computationally fast.
Q06Clustering
Why is PCA applied to the user-course matrix BEFORE K-Means clustering in the clustering-based recommender?
✅ Curse of dimensionality strikes again. If there are 500 courses, the user-course matrix has 500 dimensions. In 500D, all pairwise distances converge — K-Means can't find meaningful clusters. PCA compresses the 500 dimensions to ~50 principal components that capture most of the variance, making distances meaningful again. This follows the standard best-practice pipeline: StandardScaler → PCA → KMeans. The capstone dataset has hundreds of courses, so PCA is essential before clustering.
Q07KNN CF
In KNN collaborative filtering, what is the difference between user-based and item-based approaches?
✅ Users vs Items as the axis of similarity. User-based: "Users who rated courses similarly to you also rated this course highly." Item-based: "This course is rated similarly by the same group of users who rated your enrolled courses." Item-based CF tends to be more stable because item popularity changes less frequently than user preferences, and the number of items is often smaller than the number of users (making the item-item similarity matrix more tractable). In practice, item-based CF is used more commonly in production systems like Amazon.
Q08NMF CF
In NMF-based collaborative filtering, what do the latent factors actually represent?
✅ Latent factors = discovered hidden structure. NMF doesn't know that "data science" or "cloud computing" exist as categories — it discovers from the raw ratings that certain courses are consistently taken together. These clusters of co-enrolment become the latent factors. Factor 1 might strongly represent "Python data science courses", Factor 2 "cloud certifications" — but NMF assigned these without labels. This is why NMF is powerful: it discovers structure you never told it about, and can find patterns that explicit genre tags would miss.
Q09Surprise Library
Why is the Surprise library's cross_validate function preferred over a simple train/test split for evaluating recommender systems?
✅ Lower variance estimates. With a single 80/20 split, the RMSE you get depends heavily on which 20% happened to be in the test set. If easy-to-predict users ended up in the test set, RMSE looks great. If hard cases did, it looks bad. k-fold cross-validation splits the data k different ways, trains and evaluates k times, and averages the results — giving a much more reliable estimate of how the model will perform on truly unseen data. This is critical before reporting performance in your capstone report.
Q10Neural Embeddings
What does an Embedding layer do in a neural network recommender, and why is it better than one-hot encoding for user and item IDs?
✅ Dense + learned = far more expressive than one-hot. With 10,000 users, one-hot encoding needs a 10,000-dimensional binary vector per user — it's sparse and treats all users as completely unrelated. An embedding maps each user to a 32-dimensional dense vector learned from the data. Similar users (who rate things similarly) end up with similar embedding vectors. This dense representation is what's passed to the Dense layers, allowing the network to discover complex interaction patterns. Embedding layers are standard in every serious recommendation engine.
Q11Evaluation
What does RMSE measure in the context of rating prediction, and what would RMSE = 0.5 vs RMSE = 1.5 mean?
✅ RMSE = average prediction error in the same units as the ratings. If ratings are on a 0–3 scale, RMSE = 0.5 means predictions are typically half a point off — quite good. RMSE = 1.5 means predictions are typically 1.5 points off — worse than random guessing for a 0–3 scale. RMSE penalises large errors more than MAE (because it squares the errors before averaging). Use RMSE when large errors are especially bad; use MAE when all error sizes are equally concerning.
Q12Streamlit
Why should you use @st.cache_data and @st.cache_resource in your Streamlit app, and what's the difference between them?
✅ Caching is essential for a usable app. Without caching, every time a user changes a slider, Streamlit re-runs the entire script — reloading data from disk, retraining models, recomputing similarity matrices. With @st.cache_data, data-returning functions only run once (or when inputs change). @st.cache_resource is designed for ML models, database connections, and other global resources that should be shared across users and sessions — it avoids creating a new copy for each Streamlit session, saving memory for large models.
Q13Hybrid Systems
What is a "hybrid recommender system" and when would you build one?
✅ Best of both worlds. Every major production recommender is hybrid. Netflix: content-based for cold start, collaborative for established users. Spotify: content analysis for new songs (no ratings yet), collaborative for established ones. A pure collaborative system can't recommend new items. A pure content-based system can't surface hidden connections between genres. Hybrid systems use each approach where it's strongest — content when there's no history, collaborative when there's enough data, often blending both for established user-item pairs.
Q14Neural Networks in Rec Systems
The neural network model performs worse than NMF on the IBM capstone dataset. Is this a bug or expected behaviour?
✅ Neural networks shine at scale — not on small datasets. The capstone dataset has thousands of users and courses. Netflix-scale recommenders have hundreds of millions of users and millions of items — that's where neural collaborative filtering (NCF) earns its keep by learning rich non-linear interaction patterns. On smaller datasets, the simpler matrix factorisation methods (NMF, SVD) are less prone to overfitting and often produce better results. Acknowledging this trade-off in your capstone report demonstrates the kind of practical judgement that ML hiring managers value.
Q15Matrix Sparsity
The user-course ratings matrix is 99.5% empty. Why does this extreme sparsity make recommendation harder, and how does NMF help?
✅ Sparsity = overlap problem. To say "User A and User B are similar", you need them to have rated many of the same courses. If User A has taken 5 courses and User B has taken 6, and they share 0 in common, you can't compare them at all. NMF bypasses this by compressing all users to the same low-dimensional latent factor space — even two users with no overlap are placed in this space, and their latent representations can be compared. This is the whole point of matrix completion: learn a representation that lets you compare users even when they've taken completely different courses.
Q16TF-IDF vs BoW
TF-IDF is often better than plain Bag of Words for text similarity. What does TF-IDF do differently?
✅ TF-IDF = Term Frequency × Inverse Document Frequency. TF: how often a word appears in THIS document. IDF: how rare the word is across ALL documents (log of n_docs / n_docs_containing_word). Words like "machine" and "learning" appear in almost every ML course — they have low IDF, so their high TF barely matters. But "backpropagation" appears rarely across all courses — high IDF. If two courses both mention backpropagation frequently, that's a strong signal they're similar. TF-IDF makes similarity driven by distinctive, meaningful terms rather than universal filler words.
Q17Precision@K
Your recommender returns 10 courses for a user. Only 3 of those are ones the user actually went on to enrol in. What is the Precision@10?
✅ Precision@K = relevant items in top K / K. 3 relevant courses out of 10 recommended = 3/10 = 0.30 or 30%. This is a "ranking quality" metric that asks: "Of the K recommendations I made, how many were actually wanted?" Recall@K asks the complementary question: "Of all the courses the user would have liked, how many did I put in my top K?" Both matter — high precision but low recall means you're selective but missing many relevant items; high recall but low precision means you're casting a wide net full of irrelevant items.

Which combination correctly describes what each model uses as its primary signal?

Neural embeddings: "What learned vector best explains this user's and item's latent properties simultaneously?" (jointly trained on interaction data). Hybrid systems combine all three. Understanding which signal each approach uses tells you exactly when each will succeed and fail — and that is the core intellectual framework of the whole capstone.
